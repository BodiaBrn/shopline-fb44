
# Ретроспектива Спринту 4

- **Дата:** 21.11.2026
- **Ведучий:** Шандра Олександр (Scrum Master)
- **Учасники:** Алферов Б., Барановський Б., Костюк В., Мулявка Я., Шандра О.

## Що вдалося
- Червоні тести не «підганяли» під модуль v1: кожен із 7 дефектів має окремий звіт із точним викликом і значеннями.
- Пороги знижки, доставки й кількості перевірено з обох боків; додатково знайдено 2 дефекти (BL-20, BL-10) понад первинні 5.
- UI-тести стабільні: лише WebDriverWait, локатори `data-test`, власний браузер у кожному тесті.

## Що не вдалося
- Зміни пушили напряму в `main` без pull request — не лишалося сліду code review, а зламана компіляція потрапила в `main`.
- ID дефектів спочатку різнилися між тестами, документами й трекером.
- UI-тести спершу не відповідали кейсам спринта 3, на які посилалися.
- Документи (README, surefire, audit) оновлювали до фінального прогону — цифри розходилися.

## Що змінимо
- Усі зміни — через PR з рецензентом; перед мержем `mvn clean test` має компілюватися.
- Єдиний реєстр ID (вимоги, кейси, дефекти) заводимо на початку спринта.
- Цифри в протоколах оновлює одна людина після фінального прогону.
