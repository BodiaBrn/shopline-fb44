## 4. Питання від замовника до демо-показу
1. **Про "червоні" тести:** У звіті Surefire є тести, що впали. Чому ви не змінили очікувані значення в тестах або не вимкнули їх через `@Disabled`, щоб показати 100% успішний звіт?
2. **Про піраміду тестування:** Чому перевірку логіки розрахунку знижок (BL-30) ви написали на рівні юніт-тестів, а не через Selenium у браузері, адже клієнт купує товари саме через інтерфейс?
3. **Про стабільність:** Наш сервер іноді відповідає довго. Як ви гарантуєте, що ваші UI-тести не будуть падати через повільне завантаження сторінки кошика?
4. **Про стійкість локаторів:** Якщо завтра дизайнери змінять CSS-класи кнопки "Додати в кошик", чи доведеться команді переписувати всі автотести?
5. **Про Selenium IDE:** Ви записали кроки в Selenium IDE, який сам згенерував код. Чому б просто не залишити згенерований код як є, навіщо ви переписували його вручну?
6. **Про Headless-режим:** Ви запускаєте тести у фоновому (headless) режимі. Чи є ризик, що тест пройде успішно без вікна, але у реальному браузері з інтерфейсом він впаде?
