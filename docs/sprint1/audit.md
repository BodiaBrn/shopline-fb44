## 2. Перевірка Definition of Done (DoD)
*Аудитор здійснює фінальну перевірку готовності інкременту згідно з критеріями Спринту 1 перед злиттям у гілку main[cite: 2].*

- [ ] **BPMN-моделі:** Усі 4 моделі бізнес-процесів створено (норматив для 5 осіб)[cite: 2].
- [ ] У кожній моделі є початкова й кінцева подія, доріжки з ролями легенди, ≥1 шлюз[cite: 2].
- [ ] У наборі моделей використано ≥3 різні типи шлюзів, наявний ≥1 підпроцес, потоки повідомлень між пулами, артефакти даних та анотації[cite: 2].
- [ ] Кожна модель пройшла перевірку за чек-листом нотації (10 пунктів); збережено протокол рецензування `bpmn/review.md`[cite: 2].
- [ ] У репозиторії наявні вихідні файли (`.drawio` або `.bpmn`) та їх експорт (PDF або PNG)[cite: 2].
- [ ] **Беклог:** Створено ≥15 User Stories (норматив для 5 осіб)[cite: 2].
- [ ] Кожна story відповідає шаблону: має ID, роль, бажання, мету та пріоритет[cite: 2].
- [ ] Усі story простежуються до очікувань замовника (наявний аркуш «Очікування → stories»)[cite: 2].
- [ ] **Документація:** Файл `product.md` містить профіль, ролі, опис процесів та очікування[cite: 2].
- [ ] Статут `charter.md` доповнено розділом «Методологія, методи і прийоми»[cite: 2].
- [ ] Таблиця розподілу задач `tasks.md` актуалізована (вказані виконавці, фактичні години, статуси, посилання)[cite: 2].
- [ ] Протокол ретроспективи `retro.md` підготовлено для заповнення на занятті[cite: 2].
