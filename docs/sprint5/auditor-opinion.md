## 1. Чек-лист аудиту

Критерії зафіксовано до регресійного прогону.

### 1.1. План регресії і критерії go/no-go
- [ ] `regression-plan.md` закомічено **до** першого прогону v2 (коміт: ___, дата: ___)
- [ ] Пороги кожного критерію обґрунтовано; після прогону не змінювались (або зміну пояснено у звіті)
- [ ] У регресію включено 100 % кейсів спринта 3 і 100 % автонабору спринта 4

### 1.2. Журнал регресії
- [ ] Кожен кейс має результат v1, результат v2, дату і виконавця прогону v2
- [ ] Кожен Failed посилається на дефект (наявний або новий)
- [ ] Кожен Blocked має причину; Skipped відсутні
- [ ] Результати v2 не скопійовані з v1 (кейси перевиконано)

### 1.3. Surefire v1 / v2
- [ ] `docs/sprint5/surefire-v1/` і `surefire-v2/` збережено
- [ ] Порівняння проведено по кожному тесту, а не лише за підсумком
- [ ] Набір тестів v1 і v2 однаковий (розбіжність, напр. `ExampleTest`, пояснено)

### 1.4. Дефекти і трекер
- [ ] Кожен дефект модуля v1 (#13–#19): Verified → Closed або Reopened з фактичним результатом на v2 і датою
- [ ] Closed — лише після підтвердженого перевиконання
- [ ] Відкриті дефекти demo (#2–#11) повторно перевірено, коментар з датою
- [ ] Регресійний дефект v2 оформлено окремим звітом («регресія v2», тест, результат на v1)

### 1.5. Матриця простежуваності
- [ ] Усі вимоги SRS 1.1 у матриці (включно з виправленими в аудиті)
- [ ] Кожна вимога має ≥1 кейс або «не покрито» з причиною
- [ ] Жоден дефект не «висить» без вимоги

### 1.6. Метрики
- [ ] Усі метрики п. 3.5: формула, підставлені числа, інтерпретація
- [ ] Pass rate: Blocked і Skipped не входять у знаменник
- [ ] Числа збігаються між журналом, трекером, матрицею і звітом

### 1.7. Висновок
- [ ] Рішення go / no-go / умовний go прямо випливає з критеріїв і метрик
- [ ] Для кожного критерію вказано: виконано / не виконано, з числом
